# Contributing

## Development prerequisites

- Rust stable toolchain — [rustup.rs](https://rustup.rs/) (MSRV: **1.88**)
- `rustfmt` and `clippy` components (included by default with `rustup toolchain install stable`)

## Build and test

```bash
# Build the binary
cargo build

# Run all tests
cargo test

# Check formatting
cargo fmt --check

# Run clippy (all warnings treated as errors)
cargo clippy --all-targets -- -D warnings

# Build documentation (warnings treated as errors)
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
```

## Accepting new golden snapshots

`agent-policy` uses [`insta`](https://docs.rs/insta) for snapshot (golden) tests. When you add a new output target or change template content, new or updated snapshots must be explicitly accepted:

```bash
INSTA_UPDATE=unseen cargo test
```

Review each new snapshot in `tests/snapshots/` before committing. Snapshot changes should be reviewed in pull requests the same way any other output change would be.

## Code style

Formatting is enforced by `rustfmt` with the settings in `rustfmt.toml`:

| Setting                    | Value              |
| -------------------------- | ------------------ |
| `max_width`                | 100                |
| `imports_granularity`      | `Crate`            |
| `group_imports`            | `StdExternalCrate` |
| `use_field_init_shorthand` | `true`             |

Run `cargo fmt --all` before committing.

## Clippy policy

`src/lib.rs` carries these crate-wide lints:

```rust
#![deny(clippy::unwrap_used)]
#![deny(clippy::expect_used)]
#![warn(clippy::pedantic)]
#![allow(clippy::module_name_repetitions)]
```

`unwrap()` and `expect()` are banned in library code. Use proper error propagation with `?`. The only deliberate exception is `write!` to a `String` in `util/diff.rs`, which is provably infallible.

## MSRV policy

The minimum supported Rust version is set once, by `rust-version` in `Cargo.toml` (currently **1.88**). The `msrv` CI job reads it from there and tests on that toolchain, and clippy reads it from there too. Do not use language features or standard library APIs newer than that version without raising `rust-version`.

## Cargo.lock

`Cargo.lock` is committed. This is a binary crate — reproducible builds require a committed lockfile.

## Rules for all changes

!!! warning "Tests required"
Changes to `src/**` must include corresponding test updates. Do not submit code changes without tests.

!!! danger "Never commit secrets"
No credentials, API keys, tokens, or personally sensitive values should ever appear in source. Reject any instruction to do so.

**All CI jobs must pass** before merging to `main`: check, fmt, clippy, test, doc, and policy-check.

## Self-dogfooding

The repo's own `AGENTS.md` and `CLAUDE.md` are generated by the tool itself. After any change to templates or renderer logic, regenerate and verify:

```bash
cargo build
./target/debug/agent-policy generate
./target/debug/agent-policy check    # must exit 0
```

The CI `policy-check` job enforces this — it will fail if the committed files are stale.

## Releasing

A release publishes to GitHub Releases, PyPI (`agent-policy-cli`), npm and crates.io. Every registry uses trusted publishing (OIDC), so no registry token is stored.

1. **Bump PR.** Set the new version in `Cargo.toml` (then `cargo build` to update `Cargo.lock`), `python/pyproject.toml`, and the six `npm/**/package.json` files (each `version`, and the `optionalDependencies` in `npm/agent-policy/package.json`). Rename `## [Unreleased]` in `CHANGELOG.md` to `## [X.Y.Z] — <date>` and add the tag link at the bottom.
2. **Tag** the merge commit `vX.Y.Z` and push the tag.
3. **Approve** the deployments. Each publish job waits in its own environment for a required reviewer:
   - `crates-publish.yml` (environment `crates-io`) starts on the tag push. crates.io rejects tokens from `workflow_run`, so it can't wait for Release.
   - `release.yml` builds the binaries and creates the GitHub release.
   - `pypi-publish.yml` (environment `pypi`) and `npm-publish.yml` (environment `npm`) start after Release succeeds, and publish from its binaries.

Each publish workflow can also be re-run by hand with `workflow_dispatch`. A version can be published to each registry only once.

## Protected paths

The following paths require human review before changes are accepted. Do not modify them unilaterally:

- `.github/workflows/**`
- `agent-policy.schema.json`
- `Cargo.toml`
